# PRD — 小红书飞书扫码发布桥接器 v0.1

## 目标

把当前人工流程压缩到：

**飞书完成标题/正文/图片 → 触发生成 → 二维码自动写回 → 手机扫码 → 小红书 App 最终确认发布。**

不做内容生成，不做账号登录管理，不做自动点击最终“发布”。

## 用户故事

作为运营者，我每天会在飞书中准备多条图文笔记。  
我希望每一行笔记准备完成后，不需要复制标题、正文、图片到手机，只要生成二维码并扫码，就能进入移动端发布流程。

## v0.1 必须完成

- 读取指定飞书多维表格记录。
- 支持图文笔记。
- 支持飞书附件字段。
- 1–18 张图按飞书记录中的顺序传递。
- 调用 myaibot `/api/rednote/publish-with-upload`。
- 将二维码写回飞书附件字段。
- 将发布 URL 写回飞书。
- 将 myaibot note id 写回飞书。
- 错误写回飞书。
- 支持查询 `uploading / pending / submitted`。
- 对外媒体 URL 必须签名且会过期。
- 密钥不得进入 Git 仓库。

## 明确不做

- 不保存小红书 Cookie。
- 不做批量自动登录多个小红书账号。
- 不绕过小红书风控。
- 不声称 `submitted` 就是最终发布成功。
- 不在 v0.1 做复杂 Web 管理后台。
- 不引入数据库；状态以飞书表格 + myaibot 为准。

## 验收标准

1. 飞书一条包含标题、正文、2 张图片的记录能成功生成二维码。
2. 二维码图片自动出现在同一条记录的“二维码”字段。
3. “链接”字段可点击进入 myaibot 发布页。
4. 手机扫码后能看到正确图片顺序、标题和正文。
5. 服务器重启后不影响已生成的二维码记录。
6. API Key、飞书 App Secret 不出现在日志响应和 Git 历史。
7. 无图片、API 余额不足、飞书权限不足时，都能在“错误信息”看到可定位原因。
